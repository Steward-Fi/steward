# Account-deletion staging canary

This runbook verifies the Play account-deletion backend against an exact Steward
staging deployment. It creates and deletes only resources uniquely generated by
the canary. Do not point it at production.

## Preconditions

- The exact candidate SHA is deployed to an isolated staging environment.
- `/ready` reports `ready` with migrations, database, RLS deployment, Redis,
  Vault, and auth stores healthy.
- The staging platform key is short-lived and has only these scopes:
  `platform:tenant:create`, `platform:tenant:delete`,
  `platform:tenant-test-account:write`, `platform:user:read`,
  `platform:user-lifecycle:write`, and `platform:user:delete`.
- `STEWARD_ENABLE_PROD_TEST_ACCOUNT_TOKEN=true` is enabled only for the
  supervised staging window. Disable it immediately afterward. Never enable it
  on production.
- The operator has confirmed the exact staging hostname independently.

## Run

Keep the platform key in an ignored mode-0600 environment file or secret store;
do not put it in shell history.

```sh
set -a
source .env.staging-account-deletion-canary
set +a
bun scripts/account-deletion-canary.ts
```

The environment file must contain:

```dotenv
STEWARD_CANARY_BASE_URL=https://exact-staging-host.example
STEWARD_CANARY_EXPECTED_HOST=exact-staging-host.example
STEWARD_CANARY_PLATFORM_KEY=staging-scoped-secret
STEWARD_CANARY_CONFIRM=DELETE_DISPOSABLE_STAGING_ACCOUNT
```

The script refuses remote HTTP, URL credentials, hostname mismatches, missing
configuration, and any confirmation other than the exact phrase above. It does
not print the platform key, OTP, session token, refresh token, or test email.

## Expected proof

The canary must report PASS for:

1. Readiness.
2. Disposable ordinary-tenant creation.
3. One-time test-account enablement.
4. Confirmation that the generated email has no pre-existing owner.
5. Real authentication and canonical personal-tenant provisioning.
6. Canonical membership topology.
7. Deactivation and token revocation.
8. Rejection of the issued refresh token after deactivation.
9. Rejection of premature identity deletion while the personal tenant exists.
10. Personal-tenant deletion.
11. Identity cascade deletion.
12. A subsequent identity read returning not found.
13. Cleanup of the disposable ordinary tenant.

The test account and all tenant/user IDs come from the current canary run.
Cleanup never targets a supplied user or tenant identifier. On failure, the
script attempts cleanup only for resources it already created.

## Close the window

1. Set `STEWARD_ENABLE_PROD_TEST_ACCOUNT_TOKEN=false` or remove it from staging.
2. Revoke the short-lived canary platform key.
3. Confirm `/auth/test/token` returns 404 in production mode.
4. Confirm `/ready` remains healthy.
5. Preserve the exact deployed SHA, canary output, deployment identifier, and
   timestamps as release evidence. Do not preserve credentials or tokens.

This canary proves the live HTTP lifecycle and deletion guards. It does not
replace backup-retention verification, production change approval, or Google
Play Console declarations.
